# KTown Defense 지도 중심 팬덤 관광 경쟁 서비스 설계

**작성일:** 2026-08-14  
**상태:** 사용자 승인 설계  
**대상:** 기존 `ktown_defense` Python 도메인 프로토타입의 제품화 및 확장

## 1. 제품 정의

KTown Defense는 단순 관광지 탐방 앱이 아니다. 여러 K-POP 팬덤이 한국의 인구감소지역을 실제로 탐방하고, 승인된 현장 방문으로 관광장소 단위 거점을 만들고 방어하며, 지역 리그와 전국 시즌에서 경쟁하는 지도 중심 모바일 웹이다.

경쟁은 지역 관광 활성화를 위한 동력으로 사용한다. 상대 팬덤을 직접 공격하거나 개인 보상을 빼앗지 않으며, 실제 방문만이 거점에 영향을 준다. 시즌 우승은 방문량만이 아니라 얼마나 넓고 고르게 지역과 저노출 관광장소를 탐방했는지를 평가한다.

## 2. 확정된 제품 원칙

1. 경쟁 방식은 직접 공격 없는 건전한 영토전이다.
2. 인구감소지역의 승인 관광장소는 모든 팬덤이 점령할 수 있는 공용 전장이다.
3. 팬덤별 미션 문구·스토리·완료 연출은 다르지만 인증·점수·탈환 조건은 동일하다.
4. 아티스트 공식 연관 장소는 선택적 테마 콘텐츠와 배지로 표현한다.
5. 미션은 관광공사 데이터 기반 규칙형 초안을 만들고 운영자가 승인한다.
6. 핵심 성공 기준은 인증 고유 방문자, 고유 장소, 지역 탐방 폭, 저노출 장소 방문 증가다.
7. MVP 보상은 거점, 배지, 컬렉션, 칭호 등 디지털 명예 보상으로 제한한다.
8. 지역 리그와 전국 종합 순위를 함께 운영한다.
9. 추천 노출 점수와 거점 점수는 분리한다.
10. 첫 출시는 한 지역의 완전한 수직 사용자 흐름으로 검증한다.

- 위치·미방문·지역 다양성·저노출 기반 추천
- 팬덤별 미션 표현

- 최초 방문 포인트 원장과 역분개

## 4. 현재 구현 평가

### 4.1 재사용할 기능

- `auth.py`: 공개·회원·운영자 RBAC와 401/403 정책
- `catalog.py`: 장소 공개 필터와 공개 지도·상세 응답
- `catalog_sync.py`: 원자적 관광 스냅샷 교체와 24시간 마지막 정상 스냅샷
- `ktour_openapi.py`: `searchKeyword2`, `detailCommon2`, 오류·재시도 처리
- `checkin.py`: GPS 시작·중간·종료, 5분 체류, 카메라 사진, 일시중지·복구·30분 만료
- `verification.py`: 자동 승인·검토 필요·거절 정책
- `review.py`: 일일 재시도·48시간 이의제기·최종 판정
- `points.py`: 팬덤 잠금·멱등 outbox·최초 방문 100점·역분개
- `territory.py`: 300/1000/2000점 거점과 110% 탈환·결정론적 재생
- `season.py`: 72시간 검토 유예·2인 승인·시즌 결과 보존
- `privacy.py`, `rights.py`, `governance.py`, `reconcile.py`: 개인정보·권리·감사·복구

현재 102개 도메인 테스트는 모두 통과하며 회귀 테스트로 보존한다.

### 4.2 수정할 기능

- `PlaceArtistLink`를 장소 공개의 필수 조건에서 선택적 공식 연관 증빙으로 변경한다.
- 모든 승인 관광장소를 모든 팬덤에 공개한다.
- `LedgerEvent`에 시즌 당시의 `target_region_id`를 고정 저장한다.
- 관광 카탈로그와 거점 투영을 실제 API·DB 흐름으로 연결한다.
- 지역 리그·전국 순위·탐험 지표 투영을 추가한다.
- 인메모리 자료구조를 PostgreSQL 저장소로 교체한다.
- `KTownDefenseApp`의 일반 `200 {"ok": true}` 폴백을 실제 서비스 호출로 대체한다.

### 4.3 신규 기능

- 인구감소지역 레지스트리와 공간 경계
- 관광장소 후보와 운영자 승인
- 미션 템플릿·장소 미션·팬덤 테마
- 장소 추천 엔진과 추천 사유
- 지역 리그·전국 종합 순위
- 배지·컬렉션
- 모바일 지도 PWA와 운영자 콘솔
- 실제 HTTP API·DB·사진 저장소·outbox worker
- 관광 KPI와 경쟁 건전성 분석

## 5. 핵심 사용자 루프

1. 성인 활성 사용자가 시즌 팬덤을 선택한다.
2. 지도에서 현재 위치 주변 또는 선택 지역의 미점령·우리·상대 거점을 본다.
3. 장소 바텀시트에서 관광정보, 이동·운영·접근성, 미션, 거점 상태를 확인한다.
4. 추천 사유를 보고 미방문 장소나 새로운 지역으로 이동한다.
5. 현장에서 승인된 미션 버전으로 체크인 세션을 시작한다.
6. 포그라운드 GPS 시작·중간·종료 샘플, 5분 체류, 카메라 사진을 제출한다.
7. 자동 승인 또는 수동 검토를 거친다.
8. 최초 승인 방문이면 팬덤에 100점 원장 이벤트를 만든다.
9. 거점·지역 리그·전국 순위를 재계산하고 지도에 반영한다.
10. 개인 지역 탐방 진척도와 다음 미방문·저노출 장소 추천을 보여준다.

```text
탐색 → 이동 → 관광 경험 → 미션 → 인증
     → 팬덤 거점 변화 → 지역 리그 → 다음 지역 탐색
```

## 6. 지도와 모바일 정보 구조

### 6.1 하단 내비게이션

`지도 | 지역 리그 | 탐험 기록 | 내 팬덤`

### 6.2 지도 표현

- 회색: 미점령
- 내 팬덤 색상: 우리 거점
- 상대 팬덤 색상: 상대 거점
- 반짝임: 신규 또는 저노출 추천 장소
- 잠금: 운영시간 외·권리 만료·미션 중지
- 특별 마크: 공식 아티스트 연관 장소
- 지역 경계: 현재 지역 리그 범위

### 6.3 장소 상세 우선순위

1. 사진·장소명·관광 설명
2. 운영시간·휴무일·거리·교통·주차·접근성
3. 미션과 촬영 안전사항
4. 현재 거점·팬덤별 점수·탈환 필요 점수
5. 내 방문 기록과 추천 이유

관광정보를 경쟁 정보보다 먼저 제공해 사용자가 실제 관광장소를 이해한 뒤 이동하도록 한다.

## 7. 관광 데이터 설계

### 7.1 데이터 책임

- 한국관광공사: 장소 사실·분류·운영·이미지·출처 데이터
- 인구감소지역 공식 데이터: 대상 지역 판정
- KTown Defense: 후보·추천·미션·팬덤 테마·안전·거점 규칙
- 운영자: 장소·촬영 대상·반경·권리·미션 최종 승인

### 7.2 KorService2 사용 범위

필수 오퍼레이션:

- `areaCode2`, `ldongCode2`
- `categoryCode2`, `lclsSystmCode2`
- `areaBasedList2`, `locationBasedList2`
- `searchKeyword2`
- `detailCommon2`, `detailIntro2`, `detailInfo2`, `detailImage2`
- `areaBasedSyncList2`

선택 오퍼레이션:

- `searchFestival2`
- `searchStay2`
- `detailPetTour2`

인구감소지역 지정 여부는 관광공사 지역코드만으로 판단하지 않고 별도 공식 데이터와 매핑한다.

### 7.3 데이터 계층

`TourismSourceRecord`는 관광공사 원본 응답, 수정 시각, 스냅샷 버전, 원본 해시를 보존한다.

`PlaceCandidate`는 대상 지역, 정보 완성도, 미션 가능성, 접근성, 권리, 최신성, 반려 사유를 보존한다.

`Place`는 승인된 공개 장소로서 대상 지역, 분류, 운영시간, 휴무일, 편의정보, 이미지, 출처 수정 시각, 승인 시각, 체크인 상태와 미션 상태를 가진다.

### 7.4 후보 상태

```text
discovered → enriched → eligible → needs_review → approved → published
                                               ↘ rejected
published → suspended / removed
```

### 7.5 장소 공개 조건

다음을 모두 충족해야 공개한다.

- 대상 인구감소지역
- 유효한 관광공사 출처
- 좌표·주소·한국어 설명
- 유효한 권리
- 운영자 장소 승인
- 승인된 기본 미션
- 삭제·중지 아님

운영시간 외, 24시간 이상 만료된 스냅샷, 미션 중지, 공사·폐쇄, 안전성 재검토 상태에서는 정보는 유지할 수 있으나 새 체크인을 차단한다.

## 8. 추천 설계

### 8.1 강제 필터

- 미공개·권리 만료·체크인 중지
- 인구감소지역 외
- 승인 미션 없음
- 좌표 없음
- 24시간 이상 만료된 관광 스냅샷
- 현재 운영 불가가 명확함

운영시간 정보가 없는 장소는 자동 제외하지 않고 `운영시간 확인 필요`를 표시한다.

### 8.2 추천 점수

| 요소 | 배점 |
|---|---:|
| 실제 이동 가능성 | 25 |
| 신규 장소 탐방 | 20 |
| 신규 지역 탐방 | 15 |
| 방문 부족 장소 | 15 |
| 거점 기여도 | 10 |
| 운영시간 적합성 | 5 |
| 팬덤 테마 적합성 | 5 |
| 정보·접근성 품질 | 5 |

추천 점수는 노출 순서에만 사용하고 점령 점수에는 영향을 주지 않는다. 응답은 상위 추천 사유 두 개를 함께 제공한다.

## 9. 미션 설계

### 9.1 `MissionTemplate`

관광 분류별 한국어 제목·안내 템플릿, 기본 반경, 체류시간, 촬영 대상 유형, 안전 체크리스트와 활성 상태를 가진다.

### 9.2 `PlaceMission`

특정 장소의 버전 고정 미션이다. 장소·템플릿·버전·한국어 안내·촬영 대상·반경·체류시간·검증 모드·유효기간·상태·생성 스냅샷·승인자를 가진다.

체크인 세션은 `place_mission_id + version`을 고정해 참조한다. 진행 중 운영자가 미션을 수정해도 기존 세션의 조건은 바뀌지 않는다.

### 9.3 `FandomMissionTheme`

팬덤별 도입 문구, 성공 메시지, 시각 토큰, 공식 연관 증빙과 승인 상태를 가진다. GPS 반경·체류시간·촬영 대상·승인 기준·점수·탈환 조건은 변경할 수 없다.

### 9.4 생성과 승인

```text
관광 분류 → MissionTemplate 선택
→ 관광 사실 대입 → 안전 규칙 결합
→ PlaceMission 초안 → 팬덤 테마 초안
→ 운영자 검수 → 승인·공개
```

좌표·운영시간·촬영 대상 등 위험 필드 변경 시 `review_required`로 되돌린다. 설명 오탈자나 안전과 무관한 이미지 추가는 자동 갱신할 수 있다.

## 10. 점수와 거점

### 10.1 점수 종류

- `territory_points`: 최초 승인 방문 100점, 거점에 사용
- `exploration_metrics`: 고유 장소·지역·저노출 장소, 리그에 사용
- `engagement_metrics`: 재방문·조회·미션 시작, 운영 분석에만 사용

### 10.2 거점 규칙

- 미점령 장소에서 팬덤 300점: 씨앗 거점
- 1,000점: 나무
- 2,000점: 랜드마크
- 도전 팬덤 300점 이상이면서 소유 팬덤의 110% 이상: 탈환
- 역분개 후 소유 팬덤 300점 미만: 중립화
- 판정 순서: `created_at`, `ledger_event_id`

상대 점수 차감·체크인 방해·시간 제한 공격은 없다. 실제 신규 팬덤 구성원의 방문만 방어 점수를 추가한다.

## 11. 지역 리그와 전국 순위

### 11.1 지역 리그 점수

| 요소 | 비중 |
|---|---:|
| 거점 점유율 | 50 |
| 고유 장소 탐방률 | 30 |
| 저노출 장소 탐방률 | 20 |

저노출 장소 집합은 시즌 시작 시 직전 시즌 고유 방문자 하위 30%와 신규 공개 장소로 고정한다. 첫 시즌은 신규 장소, 운영자 지정 장소, 관광수요 데이터와 내부 노출 데이터를 사용한다.

### 11.2 대형 팬덤 완화

- 사용자·장소·시즌당 100점 한 번
- 반복 방문은 점령과 커버리지에 중복 반영하지 않음
- 공식 순위는 점수 총량보다 장소 커버리지 중시
- 성장, 신규 지역, 저노출 탐방, 분산 탐방 성취를 별도 표시
- 신뢰하기 어려운 총회원 수로 공식 점수를 나누지 않음

### 11.3 전국 점수

| 요소 | 비중 |
|---|---:|
| 지역 리그 평균 | 50 |
| 참여 지역 다양성 | 25 |
| 전국 거점 점유율 | 15 |
| 전국 저노출 장소 탐방률 | 10 |

참여 지역은 서로 다른 장소 3개 방문, 활성 장소가 3개 미만이면 전체 방문, 또는 거점 1개 보유 시 인정한다. 전국 순위에는 최소 3개 인정 지역이 필요하며 상위 5개 지역 점수 평균을 사용한다. 추가 지역은 지역 다양성에서 보상한다.

동점은 거점 수, 고유 장소 수, 마지막 거점 획득 시각, `fandom_id` 순으로 결정한다.

## 12. 시즌과 보상

MVP 시즌은 8주다. 종료 전 제출된 체크인만 72시간 검토 유예를 받고, 검토·역분개 후 서로 다른 운영자 두 명이 결과를 확정한다.

다음 시즌은 점수·소유권·레벨을 초기화하고 과거 결과·체크인·거점 이력·배지를 보존한다.

개인 보상은 지역 완주, 숨은 장소, 개척, 거점 기여, 전국 탐험 배지다. 팬덤 보상은 지역 우승, 전국 챔피언, 저노출 개척, 최다 지역, 균형 탐방 배지다. 승인되지 않은 아티스트 로고·이미지는 사용하지 않는다.

## 13. 관광 활성화와 건전성 KPI

### 13.1 핵심 KPI

- 인증 고유 방문자
- 방문된 고유 장소 수와 비율
- 사용자별 서로 다른 대상 지역 수
- 저노출 장소 고유 방문 증가율
- 상위 10% 장소 방문 집중도
- 지역 재방문율

### 13.2 퍼널

```text
지도 노출 → 장소 상세 → 길찾기 → 현장 도착
→ 미션 시작 → 제출 → 승인 → 다음 추천 선택
```

### 13.3 건전성 지표

- 팬덤별 승인 거절률
- 중복 사진·다중 계정·비정상 이동 위험률
- 신고율과 장소 민원
- 장소 과밀 집중도
- 수동 검토·이의제기 처리시간
- 안전 사고 수

개인 GPS 원본과 직접 식별자는 분석 데이터에 저장하지 않는다.

## 14. 기술 아키텍처

### 14.1 기술 선택

- 사용자·운영자 웹: Next.js App Router PWA
- 백엔드: FastAPI
- DB: PostgreSQL + PostGIS
- ORM·마이그레이션: SQLAlchemy 2 + Alembic
- 사진: S3 호환 비공개 오브젝트 저장소
- 비동기: PostgreSQL transactional outbox worker
- 지도: 교체 가능한 Kakao Maps SDK 어댑터
- 전황 갱신: Server-Sent Events + projection version 복구
- 관측성: 구조화 로그 + OpenTelemetry

Redis·Kafka·Celery는 MVP에 넣지 않는다. 애플리케이션은 마이크로서비스가 아닌 모듈형 모놀리스로 시작한다.

## 16. 핵심 트랜잭션

### 16.1 체크인 시작

### 16.2 체크인 제출

### 16.3 최초 승인 트랜잭션

- `checkin.status = approved_processing`
- 시즌 팬덤 잠금
- 승인 outbox 생성
- 멱등 결과 저장

### 16.4 outbox 처리

승인 이벤트 키를 중복 검사하고 원장 이벤트를 생성한 뒤 거점·지역·전국 투영을 재계산한다. 실패는 1초·5초·30초·2분·5분 후 재시도하고 소진 시 DLQ로 이동한다.

장소 검수 화면에는 관광공사 원문, 지도 좌표·반경, 이미지, 운영시간, 미션 초안, 팬덤 테마, 변경 비교와 안전·권리 체크리스트를 함께 표시한다.

## 19. 권리·중단·정정

권리 취소 시 공개 지도에서 즉시 숨기고 새 체크인과 진행 세션을 차단한다. 장소는 활성 분모에서 제외하며 거점은 `retired`로 역사에 보존한다.

임시 폐쇄 시 관광정보는 유지할 수 있지만 체크인은 중지하고 지역 활성 장소 분모에서 임시 제외한다.

부정 방문은 원장을 삭제하지 않고 역분개한다. 거점·지역·전국 순위를 전체 재생하고 결과가 바뀌면 정정 이벤트를 만든다.

## 20. 보안과 개인정보

- 관광공사 서비스 키는 서버에서만 사용
- 사진은 공개 URL 없이 비공개 저장
- 운영자 사진 접근은 전부 감사
- 탐색 위치는 요청 후 폐기
- 체크인 GPS·사진은 보관기한 후 삭제
- EXIF 제거 후 사진 저장
- 공개 지도·리그에 개인 식별 정보 미노출
- 최소 집계 인원 미만 분석 비공개
- 점수 조정·시즌 확정은 2인 승인
- 탈퇴 시 직접 식별자와 익명 원장 연결 제거

## 22. 단계별 출시

### Phase 0: 제품 기반 전환

FastAPI, PostgreSQL/PostGIS, 마이그레이션, 저장소, 인증, 사진, outbox와 실제 HTTP 응답을 구현한다. 서버 재시작과 프로세스 중단에도 승인 방문이 정확히 한 번 원장과 거점에 반영되어야 한다.

### Phase 1: 한 지역 수직 MVP

한 인구감소지역, 승인 장소 20~50곳, 지도·미션·체크인·검토·거점·지역 리그·탐험 기록의 전체 흐름을 실제 모바일 브라우저에서 완성한다.

### Phase 2: 다지역 탐험

3개 지역으로 확장하고 지역 간 추천, 저노출 추천, 전국 순위 초안, 배지와 팬덤 테마를 추가한다.

### Phase 3: 8주 파일럿

5개 이상 지역에서 시즌 운영, 관광 KPI, 수동 검토 SLA, 권리·안전 대응, 72시간 유예, 2인 확정과 배지 발급을 검증한다.

### Phase 4: 콘텐츠 확장

파일럿 성공 후 무장애 여행, 오디오 가이드, 두루누비 코스, 행사 미션과 지역 캠페인을 추가한다.

## 23. 구현 계획 분해

1. 백엔드 제품화: FastAPI·PostgreSQL·인증·저장소·outbox
2. 관광 데이터·장소 승인: KorService2·지역 매핑·후보·권리·동기화
3. 미션·추천: 템플릿·팬덤 테마·추천·승인
4. 체크인 수직 흐름: GPS·사진·검증·검토·원장 연결
5. 거점·지역 리그·시즌: 지역 투영·전국 순위·배지·확정
6. 모바일 지도·운영자 웹: PWA·지도·미션 UX·검수 콘솔
7. 분석·파일럿: 관광 KPI·퍼널·건전성·출시 게이트

의존 순서는 `1 → 2 → 3/4 → 5 → 6 → 7`이다. 3과 4는 공통 데이터 모델 확정 후 병렬 개발할 수 있다.

## 24. 제품 완료 기준

다음을 모두 만족해야 한 지역 수직 MVP가 완료된다.

1. 운영자가 관광공사 장소 후보를 검수하고 장소·미션을 승인할 수 있다.
2. 사용자가 팬덤을 선택하고 모바일 지도에서 승인 장소와 거점을 탐색할 수 있다.
3. 추천이 미방문·신규 지역·저노출 장소와 추천 사유를 반환한다.
4. 사용자가 현장에서 GPS·체류·사진 미션을 완료할 수 있다.
5. 승인 결과가 한 번만 원장에 반영되고 거점·지역 리그가 갱신된다.
6. 프로세스 종료·중복 요청·재처리 후에도 결과가 동일하다.
7. 권리 취소가 공개·체크인·활성 장소 분모에 즉시 반영된다.
8. 운영자가 검토·이의제기·DLQ·감사·시즌 확정을 처리할 수 있다.
9. 핵심 사용자 흐름과 운영자 흐름이 실행형 E2E로 통과한다.
10. 고유 방문자·장소·지역·저노출 장소 KPI를 개인정보 없이 집계한다.
